## Methodik und Grenzen

- Aufruf über den echten Dispatcher-Pfad `/usr/local/bin/openclaw tools call <skill> <action> <payload-json>` mit geschlossenem stdin, 75-s-Timeout, Concurrency 6.
- `fd-agent-memory-skill` und `fd-memory-recall` antworten `INVALID_PARAMS`, weil die smoke-Payload die Fachfelder (`agentType`, `query`) nicht gesetzt hat. Das beweist **Routenerreichbarkeit**, nicht Fehlfunktion.
- `fd-browser-history` und `fd-keylog-archive` antworten `LANE_VIOLATION`, weil sie vesper-only sind. Das ist die erwartete Lane-Zuordnung, kein Fehler.
- Der Chain-State (Tasks, Check-ins, Locks, Scores) wurde durch den Smoke nicht verändert; alle Aufrufe waren read-only.

## Reproduktion

```bash
# Inventar (physische SKILL.md im Bind)
docker exec openclaw-docker-openclaw-gateway-1 sh -lc 'ls -1 /home/node/.openclaw/skills/*/*/SKILL.md | wc -l'

# Wrapper-Discovery
docker exec openclaw-docker-openclaw-gateway-1 sh -lc 'openclaw tools list --json < /dev/null'

# Einzelaufruf
# Kanal-User-ID kommt zur Laufzeit aus der Umgebung (kein Literal im Repo)
docker exec openclaw-docker-openclaw-gateway-1 sh -lc 'openclaw tools call fd-scores-skill scores.get "{\"action\":\"scores.get\",\"channelType\":\"telegram\",\"channelUserId\":\"${CHANNEL_USER_ID}\"}" < /dev/null'
```
